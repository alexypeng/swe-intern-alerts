# Amazon jobs research

Researched **2026-10-05–07 (America/Toronto)**. Amazon is implemented and enabled locally; GitHub-runner validation is pending. Counts below are historical snapshots, not permanent API guarantees.

## Pagination, coverage and caps

- `result_limit=100` returns 100 rows; `500` returns an explicit error, `jobs=null` and `hits=0`. Therefore an error must be checked before accepting an empty board.
- Native internship page at offset 400 returns its final 70 rows; offset 470 returns zero. Exact page lengths, unique IDs and unchanged initial/final counts were verified.
- Unfiltered `hits=10000` is capped: [country/business facets](https://www.amazon.jobs/en/search.json?offset=0&result_limit=1&sort=recent&facets%5B%5D=normalized_country_code&facets%5B%5D=business_category&facets%5B%5D=is_intern) sum to **22,383** jobs. The US alone has 13,388, so country partitions alone do not solve the cap. The 61 business-category groups are each below 10,000 (largest: AWS, 8,014); a subsequent complete scan verified disjoint coverage (see implementation results below).
- The `is_intern` facet's 0/1 counts sum to 22,359, leaving 24 jobs unaccounted for. Do not use that facet sum as an independent all-job total. Native-filter facets each sum to its 470 results.
- Business partition probes returned AWS `hits=8015`, with 15 rows at offset 8000, and `no-business-category=595`. A later global response increased to 22,384 in both country/business facet sums as one new AWS job appeared. This validates sampled filtering/tail behavior and demonstrates count churn; it does not validate the full partition scan.
- Complete separate queries returned `intern=374`, `internship=2773`, `co-op=17`, `coop=3`. Every query had exact pages, unique IDs and stable before/after counts. After local internship-title matching, their union contained **368** IDs; **six were absent from the native filter**. One is currently announceable: [ASIC Engineer Intern, Annapurna Labs — 2027, ID 10517535](https://www.amazon.jobs/en/jobs/10517535/asic-engineer-intern-annapurna-labs-2027), which explicitly accepts bachelor's or master's students and lists Austin, Seattle and Cupertino. The other five fail existing channel or region rules.
- Native results include 108 titles without the shared internship-title signal and 30 graduate-degree titles. Native membership selects candidates; it does not replace shared eligibility checks. Counts staying unchanged cannot detect every simultaneous remove/add, and query recall/publication latency remain unverified.

## Field mapping and identity

| Posting field | First-party evidence / implemented mapping |
| --- | --- |
| Job ID | `id_icims`, the alphanumeric public URL ID (including `SF260123193`); avoid the separate UUID `id`. |
| Company | Configured display name **Amazon**; `company_name` is a varying legal employer, including Annapurna Labs. Keeping Amazon supports the existing Simplify identity. |
| URL | Validate `job_path` against `id_icims`, then use the bare English public job URL; ignore `url_next_step` (application route). Bare IDs redirect to a title slug; www/non-www hosts both served the same sampled job. Normalize verified host/slug variants by ID, including historical state and Simplify URLs. All 11 active, visible Amazon entries in the sampled Simplify feed use these public aliases. Locale variants, other domains and application aliases need separate evidence. |
| Posted date | English day-precision `posted_date`, e.g. `October  5, 2026`; `updated_time` is relative update text, not publication time. Parse whitespace carefully; no exact publication timestamp was verified. |
| Locations | `locations` contains JSON strings (frontend also accepts objects). Preserve all entries. `normalizedStateName` can supply a province/state when `region` is empty; combine city/state/full `normalizedCountryName` for shared region rules. Avoid silently treating malformed location metadata as no jobs. |
| Internship | Shared title rules select candidates from the complete scan; native membership does not establish eligibility. Returned row `is_intern` is null even for native internships; `job_schedule_type=full-time` is not an internship signal. |
| Degree | Separate `basic_qualifications` and `preferred_qualifications` HTML is available directly. No structured degree field verified. Reuse the existing required-degree parser on basic qualifications only; preferred qualifications do not establish requirements. |

Required qualifications matter: [Robotics Applied Scientist II Intern / Co-op, ID 3104589](https://www.amazon.jobs/en/jobs/3104589) has US locations and machine-learning title signals but explicitly requires PhD enrollment. Title-only degree checks would retain it. Conversely, the ASIC role accepts bachelor's/master's students. Preferred qualifications must not establish a graduate-only requirement; multilingual and misspelled qualification text remains a parsing limitation. Sample detail pages had no JobPosting JSON-LD/datePosted, so routine detail fetching adds little to the complete search rows.

## How others implemented it

Inspected actual adapter code at the pinned commits below on 2026-10-05. These are implementation observations, not proof that the repositories' current deployments work or return every job. Their source-specific logic was read; shared upstream filtering may further narrow their output.

| Implementation / pinned source | Strategy | Completeness and failure behavior |
| --- | --- | --- |
| [Job Seek](https://github.com/colophon-group/jobseek/blob/5404a5ad43b3c41241d639f270638cddd3cff3ec/apps/crawler/src/core/monitors/amazon.py) | Legacy JSON, 100-row pages, five-page bounded prefetch; on 10k cap, split by country, then job category if a country also caps. Live category slugs with a static fallback; dedup by URL. | Most relevant partition precedent. Countries come from the first capped 10k, using the fallback only if none were found; a country missing entirely from those rows can be omitted. Later page failures log and continue; country+category queries that still cap warn and return their tail truncated. No independent aggregate reconciliation or final count check. Its 50k retention limit explicitly reports truncation, which is useful but does not cover every partial-fetch path. |
| [Internship Scanner](https://github.com/internship-scanner/internship-scanner/blob/a711fac9dbe453014fd00f74acccd46b7851ce05/scraper/adapters/custom_modules/amazon.py) | Legacy JSON, European country codes, six job-category labels, keyword `intern`, 100-row pages, numeric-ID dedup. | Stops on short/empty page or safety `offset < 800`; request/HTTP/JSON failures break and return prior rows. Does not verify `hits`, API error, query coverage or changing counts. It stores only one location and slices the human-readable posted date to ten characters. Filtering/category assumptions need independent validation. |
| [Ever Jobs adapter](https://github.com/ever-jobs/ever-jobs/blob/57399c8500211e1ce57b5fbfc5e4d2b2de58b33d/packages/plugins/source-company-amazon/src/amazon.service.ts) and [constants](https://github.com/ever-jobs/ever-jobs/blob/57399c8500211e1ce57b5fbfc5e4d2b2de58b33d/packages/plugins/source-company-amazon/src/amazon.constants.ts) | Alternate POST `/api/jobs/search`, payload `{searchType: 'JOB_SEARCH', start, size: 25, filters: []}`; 500ms between pages, requested output limit defaults to 100. | Does not send keyword/location/internship filters or use `totalHits`; stops on empty/short response or the requested count. HTTP 400 becomes a normal stop; other errors return accumulated jobs with an error classification. Maps first location and `urlNextStep` to identity/URL. Useful request-shape lead for the new route, not an all-board monitor. |
| [Isaac Adjei Automations](https://github.com/zaccesss/isaac-adjei-automations/blob/7f1b5bc216284c3648c03ce7df4b44fde9c5595b/scraper/sources/amazon.py) | Legacy JSON, keyword `intern`, `loc_query=United Kingdom`, relevance sort, ten-row pages; checks primary country against GBR/IRL and shared title/location relevance. | Stops at `hits` or after offset 200 (at most 210 raw rows). Inserts qualifying rows before the entire query succeeds; request failures break and keep prior inserts. No completeness reconciliation or all-location handling. A targeted UK/Irish student tracker, not a complete Amazon discovery design. |
| [Hiring Signal](https://github.com/mosaraf-hue/hiring-signal/blob/b68d1bb37371d0a4bfd86678f94c5a51885d76b6/scraper.py) | Legacy JSON, 100-row pages until the initial `hits`, with a 500-page safety bound. | No partitioning around the 10k cap or final count validation. Failed requests stop and return existing rows; merge logic then marks absent listings closed. This is a concrete reason our adapter must discard incomplete polls rather than treating a partial list as a complete board. |

Among these adapters, only Job Seek implements cap partitioning; none inspected use a sitemap or a date-window split for Amazon. Other inspected leads were narrower: [JobsScraper](https://github.com/MabudAlam/JobsScraper/blob/d67809d9979b6f85818c3c20531930a276aa1a45/scrapers/amazon/fetch/fetch.go) requests one 100-row India page; [job-listings](https://github.com/domingos86/job-listings/blob/d8959c31feb5d96526f4d36bc4f5b2591e8a5c19/jobs/spiders/amazon.py) is an older Python 2/Scrapy implementation with three US-only keyword queries. Neither establishes current complete coverage. JobSpy's inspected scraper mapping has no direct Amazon adapter; scraper marketing/README claims alone are not implementation evidence.

The reusable ideas are public JSON, full qualifications available in search rows, bounded paging and a second partition dimension. Our established whole-board failure rule should remain stricter than the inspected adapters: no partial poll should initialize the board or be used to infer disappearance.

## Alternate POST comparison

Ever Jobs' exact anonymous payload returned 25 rows with `found=23024`; its type's `totalHits` is absent. The official [public search component](https://d2pr25vnygl9ju.cloudfront.net/_next/static/chunks/7228.2c2b4bf666a77b9d.js) uses `/api/jobs/search?is_als=true`, a `rawRequest` with external access, filter/exclusion facets, pagination and created-date sorting. Replaying that request returned `found`, `start`, `facets` and `searchHits`; fields contain string arrays, JSON-encoded locations and epoch-string `createdDate`.

This route also caps `found` at 10,000. Asking for offset 10,000 returns HTTP 400 rather than exposing the rest of the board. The CMS defaults additionally exclude `isConfidential=1`, yielding 22,172 jobs / 468 native internships, versus the concurrent legacy GET's 22,377 / 470. Removing that extra exclusion and matching the legacy exclusions (`a-confidential-job`, `isPostedExternally=0`, `isUnsearchable=1`) reconciled counts. One sampled job (`10568804`) had matching title, description, basic/preferred qualifications and all seven locations; its POST created date agreed with the GET calendar day. Full POST ID-set equivalence and latency were not tested. It does not remove the partitioning requirement, so the implementation uses the simpler GET route.

## Initial complete-scan implementation and validation (2026-10-06)

The user initially authorized complete business-category discovery after this comparison; regular polling was later replaced by the query union below. Complete discovery was selected over the native/keyword union because the native filter demonstrably omits an eligible role and keyword recall is unproven. The existing channel rules are retained with one Amazon-specific correction: the confirmed business/customer-development phrase “Business Developer” does not by itself supply a SWE signal.

- Discover business/country facets, validate equal totals and reject a business partition reaching 10,000. Fetch every partition with 100-row pages and four bounded request workers. Validate required identity/title metadata on all rows; only shared internship/undergraduate-title candidates need full posting parsing.
- Require exact page lengths, unique IDs within/across partitions, correct business membership and an actual primary-country counter matching the independent country facets. Explicit validated zero counts permit an empty board; HTTP failures, API errors, malformed candidates and incomplete pages reject the board.
- Initial live full scans repeatedly encountered count changes during the roughly 40-second fetch. Up to three passes now refetch whole changed partitions against fresh counts, keeping unchanged partitions only for this poll. Country changes without business-count changes trigger a full rescan. Unresolved churn rejects the board; no persistent cache or resume state is introduced. Count equality cannot detect every simultaneous same-count removal/addition.
- Basic-only degree extraction excludes the demonstrated PhD-only scientist role (`3104589`) and two master's-only Product Manager internships while retaining bachelor's/master's alternatives. Unknown education retains shared policy. Full location lists and calendar dates are preserved; English public ID aliases deduplicate direct, Simplify and historical records without a state reset.
- A completed local adapter scan verified **22,376 unique jobs**, **339 title-eligible candidates** and **28 announceable internships** in **41.23s**, with unchanged final business/country totals. The missing-native ASIC role `10517535` was present; the PhD-only scientist was excluded. Review then identified [Business Developer Intern 10552039](https://www.amazon.jobs/en/jobs/10552039) as business/customer development, falsely matching the generic SWE `developer` keyword. Excluding that phrase as an Amazon SWE signal leaves **27 relevant internships** in this snapshot; explicit software keywords still match.
- After the business-developer correction, the final configured full dry poll verified **22,375 jobs / 339 candidates** in **36.63s**, with **27 silently eligible Amazon postings** and no new messages. All configured source fetches succeeded; total fetch time was **45.96s**. The dry run sends nothing and saves no state.
- **340 tests passed** in 0.65s, including paging/cap reconciliation, new/removed partitions, count changes mid-page, country-only changes, bounded retry exhaustion, malformed data, basic-only degrees, all locations, URL aliases, the business-developer exclusion, and failure → silent first success → announce-once pipeline behavior. The field fixture preserves the actual ASIC response structure with reduced qualification/description text.

The read-only `validate-amazon.yml` workflow is prepared and now validates the regular query union. After the user commits and pushes, run it on GitHub and inspect its verified candidate-query log; ordinary poll success alone can hide a skipped source. Runner access and subsequent production initialization remain unverified. No workflow dispatch, Discord send or persistent-state write was performed during this implementation. The endpoint remains undocumented, education wording can be unrecognized, and publication latency is unmeasured.

## Faster regular polls selected (2026-10-07)

The user chose the native-filter-plus-keyword union to limit runtime as more company boards are added. The complete scan is retained for manual auditing rather than regular polls. Requests use native `is_intern[]=1` plus separate `base_query` searches for `intern`, `internship`, `co-op`, and `coop`. All pages are required; four workers, exact page lengths, unique IDs per query and stable before/after query counts. Overlapping candidate IDs deduplicate; inconsistent parsed details fail. Count churn retries the whole union up to three passes. A query at the 10,000 cap falls back to the complete partition adapter.

The ASIC role 10517535 was present in both eligible sets. No eligible IDs were missing or added in the union. This is one live snapshot, not a permanent coverage or performance guarantee. Regular preview: `uv run python -m intern_alerts --dry-run`. Neither sends messages or saves state. Existing degree, channel and region checks are unchanged.

Review added a regression for overlapping copies with PhD/non-PhD title disagreement. Titles are checked before eligibility filtering so an excluded copy cannot hide inconsistent job data. Final suite: 354 passed; no runtime instrumentation remains.
